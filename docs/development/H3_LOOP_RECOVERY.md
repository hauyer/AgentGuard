# H3: 调查循环状态恢复强化

## 现有状态

E2/F1 已实现：
- 强制要求 `X-Loop-Idempotency-Key` 头
- 先登记后执行的幂等机制
- 循环状态持久化到 SQLite

## 状态枚举

| 状态 | 含义 |
|------|------|
| CREATED | 已登记但未执行 |
| RUNNING | 正在执行 |
| COMPLETED | 已完成 |
| BLOCKED | 被阻塞 |
| FAILED | 已失败 |
| UNKNOWN | 外部状态不确定 |

## 测试覆盖

| 场景 | 状态 |
|------|------|
| 同一幂等键重复请求 | ✅ 已测试（G3） |
| 相同键不同参数 | ✅ 已测试（F1） |
| 进程在登记后退出 | ⚠️ 未测试（需模拟崩溃） |
| 进程在执行过程中退出 | ⚠️ 未测试（需模拟崩溃） |
| 外部 WARDEN POST 超时 | ⚠️ 未测试（需模拟超时） |
| 重启后查询预算 | ⚠️ 未测试 |
| 重启后查询决策 | ⚠️ 未测试 |
| 超出预算停止 | ✅ 已测试 |
| 连续无新证据停止 | ✅ 已测试 |

## 禁止行为

- ❌ 超时自动重新提交 POST
- ❌ 任务状态未知却报告 completed
- ❌ 重启后预算清零
- ❌ 重启后重新执行全部决策
- ❌ 将计划成功解释为审计完成

## 当前结论

基础幂等性已验证。崩溃恢复和远端对账测试需在真实环境下补充。
底层 WARDEN 无对账 API 时，应保持 UNKNOWN/BLOCKED 状态。
